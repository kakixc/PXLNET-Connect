# Обновить PXLNET Connect: воспроизводимая база, тема и Home для Beta

Этот ExecPlan — живой документ. Разделы Progress, Surprises & Discoveries, Decision Log и Outcomes & Retrospective обновляются по мере работы. Он следует правилам `C:\Users\PXL\.agents\PLANS.md`.

## Purpose / Big Picture

Пользователь сможет собрать APK из зафиксированных исходников, знать доказанный статус XHTTP и пользоваться обновлённым Home, показывающим настоящие состояния VPN. Тема будет следовать системе либо явно выбранному светлому/тёмному режиму; акцент — обоям через Monet или одному из шести ручных оттенков. Подключение с ранее сохранённым пригодным профилем не должно ждать Telegram/account API. Текущий этап охватывает фазы 0–2 и единый бета-релиз `0.6.5-beta`: пользователь уже установил промежуточную `0.6.4-beta`, поэтому versionCode повышен до 15. Выбор другого VPN-движка для XHTTP — отдельное решение пользователя, не автоматический следующий шаг. Пользователь явно попросил GitHub Release и обновление ссылок в README; старый промежуточный APK не публиковать.

## Surprises & Discoveries

- В `version.properties` уже указан Go 1.25.12, но в окружении нет Go и исходников `third_party/sing-box`; две AAR в `app/libs` тоже отсутствуют. Android SDK и NDK установлены локально.
- `PxlSubscriptionConverter.transportOptions()` понимает WebSocket, gRPC и HTTP, но не `xhttp`: при импорте transport теряется до запуска ядра. Официальный список транспортов sing-box не содержит XHTTP; требуется отдельная проверка конкретно зафиксированного ядра, а не обещание совместимости.
- `MainActivity` уже включает edge-to-edge, а тема уже использует dynamic color на API 31+, поэтому фаза 1 улучшает и делает управляемой существующую основу, а не дублирует её.
- Первый запуск libbox остановился на `missing gomobile installation`. Исходник sing-box проверяет наличие `gobind.exe` в `$GOPATH/bin`, а `gomobile bind` ищет `gobind` через `PATH`. Оба бинарника v0.1.12 установлены локально; для запуска нужно добавить `$GOPATH/bin` в процессный `PATH`. `gomobile init` здесь не нужен и в исходнике устанавливает `gobind@latest`, что нарушило бы фиксацию версии.
- `cmd/internal/build_libbox/main.go` явно проверяет строку `openjdk 17`, поэтому для сборки AAR нужен локальный JDK 17; JDK 21 может использоваться Gradle отдельно.
- Синтетический `transport.type=xhttp` на закреплённом sing-box `3001f038` завершился `unknown transport type: xhttp`. Это доказательство отсутствия поддержки в текущем ядре; TCP fallback не является исправлением.
- Промежуточная arm64-only AAR делала universal APK неполным; это исправлено пересборкой всех ABI. В worktree нет `local.properties` или `app/release.keystore`, но существующий скрипт подписи использует прежний ключ из `C:\Users\PXL\.android`; он найден и применён без копирования в репозиторий.
- После пересборки all-ABI universal debug полон; предыдущая заметка отражает только промежуточное состояние. Для проверки реального VPN, ощущения haptic, старого Android и времени запуска сейчас нет подключённого устройства/AVD. Blur и полное Expressive-переосмысление экранов ещё не реализованы.
- Сохранённый PXLNET profile лежит локально в `files/configs/*.json`. Проверка пути `MainActivity.startService0()` → `BoxService.startService()` показала: запуск читает `Settings.selectedProfile` и файл конфигурации, не ожидая `restoreTelegramAccount()` или Telegram. Недоступный API мешает первому входу/получению профиля, но сам по себе не доказывает дефект повторного подключения. Временная ошибка API в `restoreTelegramAccount()` не удаляет локальный профиль. Нужны явная UX-подсказка и регрессия автономного старта, не фиктивная правка работающего пути.
- `GitHubUpdateChecker` сейчас читает только `/releases/latest/download/SFA-version-metadata.json` и игнорирует аргумент `UpdateTrack`. GitHub `latest` исключает prerelease, поэтому честный `0.6.4-beta` prerelease не виден текущему updater; публикация без исправления не выполнит требование автообновления. Нужно отдельно читать beta-релизы для канала Beta и оставить Stable без beta, с тестом выбора и реальным HTTP-smoke после публикации.
- Синтетический VLESS + Reality без transport прошёл `sing-box check` при сборочных `with_utls`; первый запуск без build tag закономерно отказал «uTLS ... not included», что не относится к Android AAR, где `with_utls` уже включён. Backend Smart VLESS в read-only тестовом контракте использует `type=xhttp`; следовательно, позитивный Reality-check не делает эти конкретные узлы совместимыми. Текущий importer отклоняет всю смешанную подписку при одном XHTTP-узле, включая Hysteria2: если пользователь выберет UI-релиз без XHTTP-движка, это отдельный узкий дефект доступности Hysteria2, который нужно закрыть до публикации.

## Outcomes & Retrospective

Фаза 0: baseline Go/libbox и debug APK получены воспроизводимо; обе AAR содержат четыре ABI. Импорт XHTTP больше не превращает неподдерживаемый сервер в ложный TCP: пользователь получает явную ошибку. Текущий sing-box не умеет настоящий XHTTP, поэтому его интеграция не заявлена готовой. Фазы 1–2 реализованы в Android-коде; 25 JVM-тестов, debug build, signed release build и lintVital прошли. Локальные `0.6.5-beta` universal/arm64 APK подписаны прежним сертификатом и доступны пользователю. Визуальная и VPN-проверка на устройстве остаются открытыми. Полный lint ранее выявил 287 ошибок и 315 предупреждений в проекте. Backend не менялся; GitHub Release ещё не опубликован.

## Context and Orientation

Это Android-приложение PXLNET Connect. `app/` содержит Kotlin/Compose UI и Android VPN-службу; `scripts/build-libbox.ps1` собирает Go-движок sing-box в Android AAR; `patches/sing-box-pxlnet.patch` адаптирует исходники для текущего Java/Kotlin моста. `app/src/main/java/io/nekohasekai/sfa/utils/PxlSubscriptionConverter.kt` превращает VLESS subscription links в конфигурацию ядра. `app/src/main/java/io/nekohasekai/sfa/compose/theme/` задаёт Compose-тему. `app/src/main/java/io/nekohasekai/sfa/compose/screen/dashboard/PxlConnectHome.kt` рисует Home; `DashboardViewModel.kt`, `MainActivity.kt`, `constant/Status.kt` и `bg/` передают события жизненного цикла VPN. AAR — библиотека Android, содержащая собранный Go-движок. XHTTP — конкретный сетевой транспорт Xray, не синоним обычного HTTP.

Текущая точка Git — `e748adf` на `codex/pxlid-account`. `app/libs/`, `third_party/sing-box/` и `.build-tools/` игнорируются Git и используются для локальных сборочных материалов. В отдельном `pxlnet-site-account` находится backend; его менять нельзя без отдельного разрешения. Текущие Telegram login, subscription URL import, guest mode, VPN profiles, Smart Server/AUTO, Smart Routing, PXL Guard, sing-box, VLESS и Hysteria2 должны продолжать работать.

Полная карта большого refresh состоит из восьми фаз, 0–7. Сейчас реализуются только 0 (сборка и XHTTP feasibility), 1 (тема/UI foundation) и 2 (состояния/Home/скорость существующих точек подключения). Будущая фаза 3 — Smart Subscription Gateway из backend, structured nodes и состояния подписки вместе с выбранным решением для XHTTP; фаза 4 — server/preset picker; фаза 5 — subscription/account UX; фаза 6 — Settings IA; фаза 7 — polish, accessibility и полное QA. ## Plan of Work

Фаза 0 сначала восстанавливает baseline. Получить официальный zip Go 1.25.12 во внутреннюю `.build-tools/`, сверить SHA-256 с опубликованным производителем значением, распаковать локально. Клонировать официальный sing-box по точному тегу v1.14.0-beta.7 во внутренний `third_party/sing-box/`, записать commit SHA и проверить применение существующего патча. Установить переменные среды только для текущего процесса PowerShell, собрать AAR скриптом и получить debug APK. Если внешний download или build не проходит, записать точную ошибку и не утверждать, что фаза закончена. Затем запустить минимальный синтетический тест `vless://...?...type=xhttp`, который должен явно показать, сохраняется ли transport при импорте; проверить валидность полученного JSON на реально собранном ядре. Если stock sing-box не поддерживает XHTTP, оформить результаты и запросить отдельный выбор между поддерживаемым fork/patch и более крупной интеграцией Xray. Не отправлять тестовый профиль на сеть и не использовать реальные ключи.

Фаза 1: выразительный Home-язык PXLNET с высокой контрастностью, крупной первичной целью, понятным светлым эквивалентом и доступными состояниями. Сохранять System/Light/Dark отдельно от акцента. Акцент выбирается единственным параметром: обои/Monet на API 31+ либо шесть явно названных палитр; на более старом Android выбор «Обои» объясняет и применяет фирменный fallback. Цветовые роли должны учитывать светлую/тёмную тему, а не перекрашивать только кнопку. Проверить сохранение выбора, контраст, статус- и навигационные бары, динамический цвет, haptic и reduced motion. Blur применять только при явной пользе и без потери читаемости; не делать его единственным признаком состояния.

Фаза 2 начинается с тестируемой presentation-модели поверх существующих `Status` и событий переключения, не с новой VPN-службы. Шесть пользовательских состояний — Disconnected, Connecting, Connected, Switching, Disconnecting и Error — различаются по фактическим событиям; Error не раскрывает секреты. Home визуально отдаёт первенство текущему состоянию и основной кнопке, затем текущему серверу, протоколу и локальной задержке. Список прямо называется «Выбор сервера»; флаги — небольшие векторные иконки рядом с узлом, а не emoji внутри названия. Оригинальный tag остаётся нетронутым для маршрутизации. Первоначальная настройка становится просторнее и объясняет последовательность действий; пункт в App Settings повторно открывает её без очистки данных. Измерить задержку существующих Home/виджета/плитки до `Starting` и `Started`, оптимизировать доказанный общий путь. Подключение с сохранённым валидным профилем и неизвестным из-за отсутствия сети состоянием аккаунта не ждёт Telegram/API; известную локально истёкшую подписку не объявлять действующей, а отсутствие профиля вести к импорту/понятному сообщению. Обновление аккаунта не должно удалять исправный профиль при timeout/5xx; после появления сети оно выполняется отдельно. UI немедленно подтверждает действие, но не показывает ложное `Connected`. VLESS Reality проверить синтетически на текущем ядре отдельно от XHTTP и, если доступно устройство, реальным egress. После фазы 2 — подписанные arm64 и universal APK, changelog, metadata и проверка автообновления перед GitHub Release.

## Idempotence and Recovery

Зависимости скачивать только в игнорируемые каталоги внутри Connect. Перед повторным клонированием проверить существующее дерево/commit и не удалять его автоматически. При неудаче сборки оставить логи и исходники для диагностики; никогда не делать `git reset --hard`, `git clean`, force push или очистку данных приложения. Перед потенциальной заменой AAR проверить возможность повторной сборки из закреплённого тега; созданные AAR остаются ignored. Если изменения в текущем worktree неожиданны, остановить затронутый шаг и сохранить их. Rollback production вообще не входит в этот план.
